# Enforcement map

`pnpm check` is mandatory locally and in `Takewise / quality`. It runs the always-active foundation phase, root dependency audit/license inventory, then product checks automatically when app inputs exist. No path-filtered required workflow or skipped final aggregation. Root setup steps are in [tooling](../../tooling/README.md).

| Rules                    | Executable check                                                                                                           | Review still required                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Entry/skills portability | foundation.mjs checks inline routes, metadata, local licenses, JSON/YAML and personal paths; clean-copy trial              | Skill usefulness, provenance and native editor discovery                                                              |
| DEL-1 CI safety          | foundation workflow restrictions + actionlint; pinned SHA, readonly permissions, unconditional named gate, bounded runtime | Action source changes, supply-chain trust, branch protection activation                                               |
| SEC-4 credentials        | Secretlint recommended rules over repository files excluding ignored runtime/dependency dirs; no production credentials    | Novel secrets and safe logging cannot be proven by scanner                                                            |
| LANG-1                   | Prettier now; product ESLint/vue-tsc/PHP-CS-Fixer/PHPStan10 on activation                                                  | API design and type escapes                                                                                           |
| ARCH-1/2                 | Product Deptrac layers, frontend import/fetch restrictions                                                                 | Cross-module contracts, composition root and uncollected classes                                                      |
| API-1/2                  | Actual contract export/regeneration comparison, Contract PHPUnit suite                                                     | Schema completeness, stable error codes, compatibility and negative input cases                                       |
| DATA-1..5 SEC-1..3       | Required real-PG Integration suite                                                                                         | RLS tested as restricted role, controlled race barriers, lastadmin/revocation/stock invariants and migration recovery |
| UI-1/2                   | Vitest, Playwright and axe in key-flow tests                                                                               | Keyboard/screen-reader/zoom checks and correct state coverage                                                         |
| JOB-1                    | Queue encryption/rollback/expiry tests in Integration                                                                      | Provider behavior, key rotation and failure recovery                                                                  |
| QA-1                     | Separate nonempty PHPUnit suites, Vitest nonempty run, Playwright no focused/flaky tests                                   | Required scenario completeness; test count is not behavioral coverage                                                 |
| DEL-1 dependencies       | frozen pnpm installs, Composer validation/lock install/audit, package license inventories                                  | License obligations, install scripts, high-risk transitive changes                                                    |
| Recovery/release         | No active deploy jobs; production prerequisites documented                                                                 | Restore exercise, migration compatibility, actual activation and ownership                                            |

Checks propagate nonzero exit codes. Missing applications are explicitly INACTIVE; missing tools/config/tests for detected applications are errors. Tests of gate behavior use disposable fixtures, never dummy product tests. Foundation fixtures exercise policy code; they do not establish ERP correctness.

`pnpm format` changes formatting intentionally. Dependencies and vendored skills are excluded from formatting so upstream license/content stays intact. Secretlint excludes ignored local secrets but repository review must reject staging them; no scanner guarantees every secret is detected. Do not add blanket suppressions or continue-on-error. Policy changes require lead review; until remote protection is activated this is a review obligation, not an enforced server setting.

No hooks modify developer Git configuration. Use [remote activation](delivery.md) to configure actual required check and reviewer identities, then test a failing PR. Remote branch enforcement and production deployment remain unverified.
