# Engineering rules

Each row names automation or a specific review obligation. Product checks become active with app inputs; before then these are requirements for the first implementation PR, not claims of passing product tests.

## Structure and dependencies

**ARCH-1.** `backend/src/<Module>/{Http,Application,Domain,Infrastructure}` for Identity, Companies, Customers, Invoices, Inventory and Notifications. Http maps validated DTOs and responses; Application performs authorized use cases and transactions; Domain owns invariants and pure values; Infrastructure implements repositories and external adapters. Domain must not depend on Symfony, Doctrine, HTTP or other modules' Infrastructure. Application may use Domain and declared ports, never controllers. One module accesses another through its Application port, not its repository. Composition root `backend/config/` wires adapters. Check Deptrac plus review module APIs.

**ARCH-2.** `frontend/src/features/<feature>/` owns views, queries, forms and component tests; `src/api/` owns generated schema/client/problem decoding; `src/router/` owns routes; `src/shared/` is business-agnostic UI. Shared must not import features. No direct fetch outside api adapters; no backend entity serialization. Check ESLint restrictions, contract generation and review.

**LANG-1.** PHP strict types, final classes unless extension is deliberate, typed DTOs/value objects, constructor injection, no container lookup. PHPStan level 10 with Symfony/Doctrine extensions; no blanket baseline. Vue Composition API `<script setup lang="ts">`, strict TS, explicit component props/events, no `any` workaround. Format with PHP-CS-Fixer/Prettier, ESLint/vue-tsc. Avoid premature abstractions and packages; review boundaries before extracting shared code.

## HTTP contracts

**API-1.** Version routes `/api/v1`, same origin. Routes and request/response DTO attributes are schema authority; Nelmio exports `backend/openapi.json`, generator writes `frontend/src/api/schema.d.ts`. Commit both; freshness checks compare actual output, not file timestamps. Review compatibility; response conformance tests validate success and problem schemas (including forbidden/not-found). Use UUID strings, ISO 8601 UTC timestamps, YYYY-MM-DD business dates, decimal strings for money and integers for units. Never expose entities, internal IDs not in schema or stack traces.

**API-2.** Reject unknown request fields, wrong types and excess precision. Configure Serializer `allow_extra_attributes: false`, required constructor fields and Validator constraints; MapRequestPayload `acceptFormat: 'json'` on JSON routes; a shared exception subscriber normalizes serializer/validator errors. No implicit numeric or Boolean coercion. 400 malformed JSON, 415 unsupported media, 422 validation; 401 invalid session, 403 role denial, 404 nonexistent or foreign-company subject, 409 state/version/stock conflict, 429 throttling, 503 temporary unavailable. Problem JSON has `type`, `title`, `status`, `code`, `requestId`; `errors` contains safe field paths/messages for 422. Request IDs are server-generated or strictly validated, never raw log injection. Check negative DTO tests and contract tests.

**API-3.** Lists use bounded pagination (default 25, maximum 100) and allowlisted sorts/filters. Explicit 422 on invalid bounds. Never accept company authority from body/query/header; derive from active authenticated membership. Client-selected resource UUIDs remain untrusted. Review SQL plans for actual list queries, require indexes on company+filter/order and FK columns. No speculative performance promises; track latency/error/DB saturation once deployed.

## Security and identity

**SEC-1.** Separate platform identities and client memberships. Platform admin cannot enter company data via a universal admin voter or spoofed scope. Client staff cannot invite/manage roles/accounts or void invoices. Resolve subjects through company-scoped repository before voter; voter checks active actor, company, action and object state. Every operation checks server authorization; UI hiding is not authorization. Cross-tenant 404; same-tenant wrong role 403. Integration tests cover role/tenant matrix; lead reviews every new action.

**SEC-2.** PostgreSQL-backed server sessions, production cookie `__Host-takewise` Secure/HttpOnly/SameSite=Lax, Path=/ and no Domain. Local HTTP uses explicitly development-only cookie name; production must refuse insecure cookie config. Same-origin `/api`; no wildcard credentialed CORS. 30-minute idle, 8-hour absolute expiry verified server-side per request. Rotate session ID and CSRF token after login. Session-bound synchronizer CSRF token for every mutation including login/logout; pre-login GET `/api/v1/session` establishes anonymous session and returns token with `Cache-Control: no-store`; submit `X-CSRF-Token` and verify constant-time. Origin checks are additional, not replacement. Rate-limit login/reset/invite by normalized account plus trusted client IP; initially 5 login failures per account/15min and 30/IP/15min, reset 3/account/hour and 20/IP/hour, invites 20/company/hour. Store limit state centrally in PG; proxy trust explicitly configured at hosting activation. Rate-limiter bounds are delegated engineering defaults; monitor without exposing account existence.

**SEC-3.** Password length 15–128 Unicode characters, spaces allowed, no forced composition. Symfony Argon2id; verify extension available and test hash algorithm (no silent fallback). Invitations expire 48h, resets 30min, 32 random bytes encoded URL-safe; store SHA-256 hashes only. Atomic single-use consumption with row locks. Generic public reset response; no logs of tokens/passwords/session/CSRF. Role, disable, password reset or password change increments account authentication version and revokes all sessions in the same transaction. Requests check current version/active membership; mutations lock the account for a current check so revoked sessions cannot start a new mutation after revocation commits. Preserve last active client admin by locking company before membership modifications. See recipes; race tests mandatory.

**SEC-4.** Secrets injected independently per environment; ignored `.env` local only. No real secrets in fixtures. TLS mandatory in production; CSP, frame-ancestors, nosniff and referrer policy configured with assets before deploy. Audit actor/company/action/subject/time/request ID/outcome without PII payloads. Record role/permission changes, company provisioning, invoice lifecycle and stock adjustments. Logs are structured and redact credentials; failed login is generic. Security tests and lead review; secret scanner is incomplete defense.

## Persistence and business integrity

**DATA-1.** All company business tables have nonnullable company_id, tenant-leading indexes, RLS ENABLE + FORCE and both USING/WITH CHECK for a transaction-local scope. Composite unique `(company_id,id)` and composite FKs prevent cross-company references. Restricted app role is not owner, superuser or BYPASSRLS. Every client operation opens a transaction and uses parameterized `set_config('app.company_id', company, true)`; absent scope denies, never falls back to all rows. Connection pool reuse tests required. Identity/control-plane tables use a distinct restricted connection/schema with explicit grants and no business table rights. Shared coordination schema holds company rows, prefix/counter and narrow provisioning/increment functions as specified in patterns. Runtime never uses migration credentials.

**DATA-2.** Price/totals API decimal strings, exact brick/math operations, numeric(18,2), nonnegative; reject more than 2 fraction digits and overflow, do not round silently. Whole quantities integer 1..2147483647 per invoice line; stock balance 0..2147483647 with overflow checks, signed adjustments within balance range. Total bound 9999999999999999.99 including aggregation; duplicate product lines normalized before stock checks. No discounts/tax calculations until agreed. Server computes line and invoice totals; client totals illustrative only. Dates in UTC with Asia/Kolkata display, business dates remain date-only. Review arithmetic and edge tests.

**DATA-3.** Draft invoice mutable with optimistic version; issued immutable (customer/product descriptions and prices snapshot at issue), correction void+replace. One warehouse, append-only stock movements; opening/manual adjustment requires actor/reason/time, never direct balance edit. Issue counter starts 1, monotonically increases with no year reset; prefix frozen after first issue, assigned by Takewise before first issue; unique company+number. Voids return stock once and never recycle number. Only client admin can void. Insufficient stock rejects whole transaction. Lock order company coordination row, actor, invoice, counter, sorted product balances; all competing operations follow the same order. Locks and counter increment live in the same DB transaction; avoid external I/O inside. Deadlock/serialization retries use fresh EntityManager and same idempotency key, at most 3 attempts with jitter; exhaustion 503. Do not retry validation or insufficient stock. Transaction tests on real PG prove atomicity.

**DATA-4.** Mutation idempotency: UUID key required for issue/void/stock adjustments/provision/invite/reset consumption. Unique scoped operation key with canonical request hash and committed result in same transaction; same key/hash returns stored result, different hash409. Public auth flows scope keys to token hash or anonymous session, never an arbitrary company header. Financial mutation keys retained with records; identity keys expire only after associated token expiry and contain no secret. Draft edits require expected version; concurrent stale write409. Archive referenced customer/product rather than deleting; snapshot preserves historical display. Sensitive retention, exports and destructive deletion await legal/product decisions, not arbitrary TTLs.

**DATA-5.** Migrations are reviewed SQL/Doctrine migrations with expand/contract strategy, bounded backfills, validation before constraints and lock impact evaluated. Never run schema:update in production or automatic destructive down migrations. Test empty DB and upgrade from previous schema with restricted role; prove RLS policy/grants and restore strategy. Migration role only in release job. Track schema version in artifact/release record.

## Frontend and background work

**UI-1.** Vue Query keys include company/account and resource/filter identifiers; clear all query data on logout, 401, revocation and account change. Never persist private query cache in browser storage. GET retries maximum2 only transient network/5xx; mutations retry:false; explicit user retry preserves operation key. Disable duplicate submit for UX, not integrity. No optimistic invoice or stock updates. Handle loading/empty/error/forbidden and expired-session states, preserve recoverable form input in memory, bind 422 errors to fields. Abort stale requests on logout. Component tests assert these transitions.

**UI-2.** Semantic labels, keyboard flow/focus, error summaries, aria-live status where needed; dialogs trap/restore focus; contrast and reduced motion meet WCAG2.2AA. Playwright axe scans key routes plus manual keyboard, zoom and screen-reader checks in PR. Do not install React-targeted accessibility helpers or UI packages without evaluating Vue fit.

**JOB-1.** Mailer/Messenger Doctrine queue uses same DB transaction/connection for intent enqueue. Store encrypted credential-bearing payload via libsodium secretbox with random24-byte nonce and separate32-byte key (versioned key ID); only hashes in token records. Three retries at 1,4,16 seconds with bounded jitter, then failed transport; worker validates token not consumed/expired and account eligible before sending (pending invitation or active reset, as the recipe specifies). SMTP may duplicate after crash; exactly-once delivery is not promised. Delete encrypted data after successful delivery or token expiry, including failed queue payload; retain redacted metadata. Operator retry cannot resurrect expired credentials. Queue handler logs no link or recipient body. Provider and key custody block production activation.

## Delivery and verification

**QA-1.** PHPUnit unit + real PostgreSQL integration (no SQLite substitute), Vitest/Vue Test Utils behavior tests, Playwright authenticated roles/key flows and axe. Require nonzero executed test counts and fail skipped/incomplete backend suites and focused tests in CI. Cover all critical workflows in recipes. Coverage percentages alone are not acceptance. Contract freshness, conformance, Deptrac, PHPStan, ESLint, types, formats and builds all required when their application exists.

**DEL-1.** Root foundation command always runs routing, safety, path/secrets/config checks. Product detection cannot depend on a developer opt-in variable. Lockfiles, dependency audit, license report and pinned CI actions are mandatory. Readonly PR tokens, hosted disposable runners, no production secrets, no pull_request_target. Release tested immutable artifacts, reviewed migrations, readiness smoke checks and rollback limits per delivery guide. Lead reviews check/policy changes; remote admin must activate merge requirements.
